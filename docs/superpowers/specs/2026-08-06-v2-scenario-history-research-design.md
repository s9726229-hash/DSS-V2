# DSS V2.0 情境化歷史研究設計

## 目標與邊界

V2 將歷史研究依實際決策情境分成建立部位、加碼與再進場。系統只呈現個人歷史資料的研究觀察，不提供自動買賣指令。

本設計不修改已推送的 V1.9、Worker、FinMind 憑證、資料保存原則，或既有通用 Profile 的內容。

## 共用研究引擎

研究引擎接受研究情境 `establish`、`add-on` 或 `reentry`，以相同的流程處理：

1. 選取該情境的已合併交易事件。
2. 依事件交易日截斷市場資料，避免使用事後資訊。
3. 計算技術與籌碼快照。
4. 計算事件後的還原價報酬。
5. 依資產類別與情境分開統計完整樣本、個人基準中位數與證據強度。

個股使用 20 個交易日觀察窗，ETF 使用 60 個交易日觀察窗。未走完其觀察窗的事件保留顯示，但不得納入該觀察窗統計。

個股與 ETF 絕不混樣本；建立部位、加碼、再進場也絕不混樣本。

## 事件情境

- 建立部位：買進前持股為零，且此前未曾完整結束該標的部位。
- 加碼：買進前仍持有該標的，買進後持股增加。
- 再進場：曾完全賣光後，買進前持股為零的再次買進。
- 同標的同交易日的同類買進合併成單一研究事件。
- 部分賣出後再次買進仍是加碼；現沖不構成研究事件。

加碼事件額外保留加碼前持股、加碼前加權平均成本與加碼成交價。相對均價為 `(加碼成交價 - 加碼前平均成本) / 加碼前平均成本`。原始相對均價必須保留，讓本機個人歷史資料可產生或調整區間；不得使用網路建議門檻。初始研究設定可提供可調的對稱預設值正負 3%，且每份儲存的研究結果必須記錄其參數快照。

## 歷史研究頁

歷史研究頁的第一層分頁為：建立部位、加碼研究、再進場研究、交易紀錄。

三個研究情境共用摘要結構：資產類別切換、事件數、完整樣本／未完成樣本、個人基準中位數、證據強度、指標分頁與候選／觀察結果。

- 建立部位與再進場使用既有四個指標：20MA 乖離、外資、投信、融資。
- 加碼使用同一四個指標，另加「相對均價」分頁。該分頁顯示低於、接近、高於加碼前均價的本機研究觀察。
- 再進場的前次出清價與出清至再進場間隔只在事件明細顯示作背景，不形成獨立評分。

資料不足或未完成觀察窗時，介面必須明確說明原因與樣本數，不得產生買賣用語或建議按鈕。

## 證據強度與比較

同一資產類別、同一決策情境的其他事件構成主要比較基準。加碼可額外將同類別、同期間建立部位列為背景參考，但不得取代主比較。

- 0–4 個完整樣本：資料不足，只列個案。
- 5–9 個完整樣本：初步觀察，不產生規則。
- 10 個以上且跨至少兩個完整檢查點方向一致：可標示為值得持續追蹤。

任何結論均限於歷史樣本觀察。

## Profile 與今日總覽

研究候選只能由使用者明確套用到建立部位、加碼或再進場各自的 Profile。既有 V1 通用 Profile 不自動複製或搬移。

今日總覽只讀取明確對應該決策情境的 Profile；沒有對應 Profile 時，必須顯示未設定。

## 交付與驗證順序

1. 共用引擎：以單元測試驗證事件選取、同日拆單合併、情境與資產類別隔離、觀察窗，以及未完成樣本排除統計。
2. 歷史研究頁：以元件測試驗證情境分頁、相對均價、樣本標示、資料不足文案與無買賣指令。
3. Profile 與今日總覽：以測試驗證只能明確套用對應情境的 Profile，且沒有對應設定時誠實顯示。

每一段完成後先執行目標測試與型別檢查，再開始下一段。整體完成前，執行完整測試、型別檢查與建置驗證。
