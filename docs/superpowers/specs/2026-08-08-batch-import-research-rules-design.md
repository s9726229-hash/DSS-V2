# 目前規則一次帶入研究參數設計

## 目標

在「目前規則」頁提供單一入口，將建立部位、加碼、再進場三種情境的最新研究參數一次帶入 Profile。個股與 ETF 分開，只有使用者預覽並明確確認後才寫入；此功能不修改交易、研究紀錄、市場快取或庫存快照，也不代表買賣建議。

## 已確認決策

- 一次處理全部三種情境，不只目前分頁。
- 每個 `情境 × 資產類別 × 指標`只取最新研究紀錄的 `normal`（一般／中性）候選；`pullback`與`overheated`不會同時套用。
- 有可用候選時，覆蓋該格既有研究規則與手動規則。
- 沒有可用候選時保留該格原值，不清空，也不阻擋其他候選。
- 所有可用的一般／中性候選都可納入，包括資料不足、初步觀察、重疊敏感或其他未達 `worth-tracking` 的結果。
- 批次含任何弱證據候選時，最終確認前只需一次整批勾選；套用後每個邊界仍保留原本的證據等級與「證據不足仍套用」標記。
- 取消預覽不寫入；確認後只呼叫一次 Profile 儲存，避免部分成功。

## 資料來源與候選規則

規則頁讀取本機 `researchRuns`，分別選出 `establish`、`add-on`、`reentry` 最新的一筆搜尋紀錄。舊紀錄缺少 `scenario` 時沿用既有相容規則，視為 `establish`；不會拿建立部位紀錄補加碼或再進場。

每筆最新紀錄依該情境的指標清單擷取：

- 建立部位：20MA 乖離、外資流向、投信流向、融資流向。
- 加碼：上述四項加上相對均價。
- 再進場：與建立部位相同四項。
- 每項再分個股與 ETF，合計最多 26 個候選。

候選必須存在 `normal` band，且上下界都是有限數字。結果、band 或任一邊界缺少時，該格分類為「沒有新候選」並保留現值。這也涵蓋舊版研究紀錄缺少後來新增指標的情況。

## 模組邊界

### 批次候選整理器

建立純資料模組，輸入正規化後的 `ResearchRunRecord[]`與目前 Profile，輸出：

- 每個情境使用的研究日期、run id、事件數與完整樣本數。
- 可套用候選清單，每項包含情境、資產類別、指標、一般區間、證據、原因與來源 run id。
- 將新增、覆蓋、無候選保留的項目清單與計數。
- 是否包含弱證據候選。
- 套用後的完整 Profile 預覽值。

整理器不讀寫 IndexedDB、不接觸 React，也不自行產生研究結果，便於直接測試互斥、覆蓋與缺漏行為。

### 規則頁協調

`ProfilePage`在載入現有 Profile 時一併讀取研究紀錄，提供「從最新研究一次帶入」按鈕。按下後只建立預覽，不立即寫入。

若三種情境都沒有任何可用候選，按鈕維持可說明狀態並顯示「目前沒有可帶入的研究參數」，不開啟空白確認視窗。

### 批次預覽

預覽對話框依建立部位、加碼、再進場分組，顯示：

- 各情境採用的研究日期與樣本摘要；沒有研究紀錄時明確標示。
- 新增、覆蓋與無候選保留數量。
- 每個候選的資產類別、指標、原值、新值及證據等級。
- 被全面覆蓋的手動規則須明確標示，不以一般「更新」文字掩蓋。
- 無候選項目預設收合成摘要，需要時可展開查看。

若存在弱證據，確認按鈕預設停用，使用者勾選「我知道其中包含未通過驗證的參數，仍要整批套用」後才可繼續。沒有弱證據時不顯示勾選框。

## 寫入與後續狀態

確認時把所有可用候選依序套用到記憶體中的 Profile，再以單次 `writeProfile(nextProfile)` 保存。每個可用候選都以 `normal` band 寫入上下界，保留：

- `sourceRunId`
- `sourceEvidence`
- `appliedDespiteWeakEvidence`
- 更新時間

成功後規則頁的 saved 與 draft 同步換成新 Profile、關閉預覽，並顯示整批套用結果。無候選格維持原值。寫入失敗時保持原 saved Profile 與預覽內容，顯示錯誤並允許重試；不得只更新畫面狀態假裝成功。

切換到今日總覽後，既有情境選擇流程會讀取新 Profile；批次功能本身不觸發市場同步或重新研究。

## 測試與驗收

### 資料層

- 每個情境只選最新紀錄，且不跨情境借用。
- 舊版缺 scenario 的紀錄只屬於建立部位。
- 只取 normal band；每個 key 最多一個候選。
- 建立與再進場各最多 8 項，加碼最多 10 項，總數最多 26。
- 可用候選覆蓋研究來源與手動規則。
- 缺少結果、normal band 或完整上下界時保留原值。
- 弱證據候選保存正確來源與警告標記。

### 畫面層

- 規則頁能從單一按鈕開啟三情境批次預覽。
- 預覽正確顯示研究日期、新增／覆蓋／保留計數與手動規則警示。
- 有弱證據時未勾選不能確認；勾選後可確認。
- 取消不呼叫寫入。
- 確認只寫入一次完整 Profile，成功後立即反映在三個情境分頁。
- 全部無候選時不開空白對話框，並提供明確訊息。
- 寫入失敗不改 saved Profile，且可重試。

### 回歸驗證

- 現有逐格手動編輯、清空、預覽並儲存流程維持可用。
- 歷史研究原有逐項「加入 Profile 候選」流程維持可用。
- 今日總覽仍只讀已確認保存的情境 Profile。
- 前端完整測試、Worker 測試、TypeScript 型別檢查與正式建置全部通過。

## 非範圍

- 不自動選 pullback 或 overheated band。
- 不在規則頁重新執行研究或回補市場資料。
- 不排程自動更新 Profile。
- 不把缺少候選視為清除規則指令。
- 不自動發布、推送、合併或部署 V2 分支。
